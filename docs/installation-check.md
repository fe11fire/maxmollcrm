# Проверка установки с нуля

Дата: 2026-11-13. Исходный код: локальный коммит `fab7e32`.
Проверялись отслеживаемые файлы Git, без существующих `.env`, `vendor`, кешей приложения и данных MySQL.
Изменять код приложения для прохождения установки не потребовалось.

## Изоляция

Для проверки создан архив `git archive HEAD` и распакован в отдельный временный каталог.
Использован отдельный проект Compose `maxmollcrm-install-check`.
Временный override изменял только публикацию портов и хранение рабочей MySQL:
API — `127.0.0.1:18080`, порты MySQL/phpMyAdmin не публиковались,
данные MySQL — новый именованный том вместо рабочего каталога `docker/volume/mysql`.
Тесты использовали свой mysql-test внутри той же отдельной сети.
Текущий проект Docker и его БД для этой проверки не пересоздавались и не очищались.

## Окружение

- Windows / PowerShell, Docker Desktop с Linux-контейнерами.
- Docker Compose v5.7.0.
- PHP 8.2.35, Laravel 12.3.0 из composer.lock.
- MySQL 8.4.4 из образа mysql:8.
- Образы PHP и Composer собраны с `--no-cache`.

Версии образов могут меняться при повторной сборке; значения выше фиксируют фактическую проверку.

## Что подтверждено и что остаётся за пределами проверки

Команды первоначальной настройки из README проверены на чистой копии файлов проекта.
Для запуска API достаточно Docker: локальные PHP, Composer и Node.js не понадобились.
Сборка образов и первая установка пакетов требуют доступа в интернет.

Это не полный аудит API, безопасности или production-развёртывания. Измерение нагрузки,
процент покрытия тестами, CI/CD и установка на Linux/macOS в эту проверку не входили.
При повторении проверки используйте свободные порты и новую БД, не рабочие данные.
